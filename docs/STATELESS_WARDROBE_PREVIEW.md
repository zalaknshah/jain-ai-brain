# Stateless wardrobe inventory preview

`jace preview-wardrobe --stdin --allow-local-disclosure` lets you review the existing typed wardrobe checklist without first saving an inventory as memory. Provide exactly the inventory JSON described in [Wardrobe planner](WARDROBE_PLANNER.md): an `items` list and a `minimum_ready` object with all five categories. There is no user ID, saved-record selection, memory scope or corpus argument. The command does not instantiate the cognitive engine, open a database, load canonical sources, call a model or save a record. Environment-configured database, corpus and provider settings are not used.

This is a local preview of user declarations, not a saved-inventory update. Existing inventory validation and plan calculations are reused unchanged: owned-ready counts, declared minimum shortfalls, ownership review, explicit preservation, repair/fit/uncertainty checks, and entered-order possible-surplus review. The output adds `mode: "stateless_preview"` and `inventory_saved: false` to the ordinary pure planner result. `action` stays null and `actions_executed` stays false. No repair, donation, disposal, purchase, contact or physical action is authorized.

Both flags are required before stdin is read. Input is strict UTF-8 JSON with duplicate keys rejected, bounded to 65,536 bytes (at most 65,537 read to detect overflow). The existing inventory schema still limits rows, labels, categories, choices, per-row/total quantities and declared minimums; unknown fields fail closed. This synchronous stream read may wait for input/EOF and has no absolute deadline.

**Disclosure:** unlike the lexical diagnostics command, this preview includes the supplied inventory labels and declarations, plus its checklist. `--allow-local-disclosure` explicitly permits that local stdout output; it is not permission to send or publish it. Input files, terminal echo/history, process environment, other software, stdout redirection and logs may retain or expose the inventory. Stateless does not mean secret, anonymized or erased. The command writes no inventory file or application memory of its own.

Validation failures return status 2 with a generic error and no preview. The complete output is serialized and checked against a 131,072-byte limit before writing. Device write/flush failures produce a generic incomplete-output warning and nonzero status; already written bytes may remain, and Python shutdown flushing can alter the process exit code. Consumers must discard output on failure and must not treat redirection as atomic storage. Generic handling covers input/planner validation and output IO, not arbitrary interpreter failures or ordinary argument-parser errors.

The checklist does not verify real garments, ownership, needs, suitability, religious teachings or resource savings. It adds no reviewed corpus, trained intelligence or new planning rules. Original synthetic tests exercise the stateless route, unchanged plan output and ownership/preservation priorities, bounds, disclosure, no engine/database/corpus construction, output failure and a real subprocess pipe. These do not establish native Windows, actual browser, scholarly, physical-safety or production qualification.
